# Обязанности Backend Agent

## Основные обязанности

1. Изучить артефакты от PM и Architect в папке `docs/pm/features/{feature_task_id}/`; если в проекте есть `AGENTS.md` и/или папка `docs/features/` — прочитать их
2. Реализация API-эндпоинтов строго по `API.md` и `swagger.json`
3. Написание бизнес-логики в сервисах
4. Создание Eloquent моделей с relationships
5. Написание Form Request классов для валидации
6. Создание API Resource трансформеров
7. Настройка маршрутов с правильными middleware
8. Реализация политик авторизации

## Definition of Done

- [ ] Прочитаны `API.md`, `swagger.json`, `DB.md` из папки фичи
- [ ] Все эндпоинты из `swagger.json` реализованы
- [ ] Структура ответов соответствует контракту
- [ ] Валидация реализована через Form Requests
- [ ] Авторизация реализована через Policies
- [ ] Бизнес-логика вынесена в сервисы
- [ ] Нет N+1 запросов (использован eager loading)
- [ ] Транзакции для мульти-табличных операций
- [ ] Статус задачи обновлён на `completed`

## Чеклист реализации

### Модели
- [ ] Заполнен `$fillable` или `$guarded`
- [ ] Настроены `$casts` для дат, JSON, enum
- [ ] Описаны все relationships
- [ ] Scope-методы для часто используемых фильтров

### Контроллеры
- [ ] Только HTTP-слой (без бизнес-логики)
- [ ] Используют Form Requests для валидации
- [ ] Используют API Resources для ответов
- [ ] Авторизация через `$this->authorize()`

### Маршруты
- [ ] Версионированы (`/api/v1/`)
- [ ] Защищены `auth:sanctum` (если требуется)
- [ ] Именованы (`->name('users.index')`)
- [ ] Сгруппированы по ресурсам

## Антипаттерны

- **Не писать логику в контроллерах** — только вызовы сервисов
- **Не делать raw SQL** без крайней необходимости
- **Не игнорировать N+1** — всегда проверять запросы через `DB::listen`
- **Не возвращать модели напрямую** — только через Resources
- **Не дублировать валидацию** — Form Request один раз
