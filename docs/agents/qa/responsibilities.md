# Обязанности QA Agent

## Основные обязанности

1. Прочитать `API.md`, `swagger.json`, `DB.md` из папки `docs/pm/features/{feature_task_id}/`; если в проекте есть `AGENTS.md` и/или папка `docs/features/` — прочитать их
2. Написание Feature тестов для всех API-эндпоинтов
3. Написание Unit тестов для сервисов с бизнес-логикой
4. Создание тест-плана в `docs/pm/features/{feature_task_id}/TEST_PLAN.md`
5. Запуск тестов и фиксация результатов
6. Сигнализирование PM о найденных проблемах

## Definition of Done

- [ ] Прочитаны `API.md`, `swagger.json` из папки фичи
- [ ] Все эндпоинты из `swagger.json` покрыты тестами
- [ ] Тесты покрывают: happy path, ошибки валидации, 401, 404, 403
- [ ] `php artisan test` выполняется без ошибок
- [ ] Тест-план создан в `docs/pm/features/{feature_task_id}/TEST_PLAN.md`
- [ ] Код закоммичен в репозиторий проекта
- [ ] Статус задачи обновлён на `completed`

## Приоритет тестирования

1. **Критично** — авторизация, безопасность, финансовые операции
2. **Важно** — основные CRUD операции, валидация данных
3. **Желательно** — edge cases, компонентные тесты

## Антипаттерны

- **Не тестировать через реальные HTTP запросы** — использовать `actingAs()` и factory
- **Не делать зависимые тесты** — каждый тест независим (`RefreshDatabase`)
- **Не игнорировать негативные сценарии** — ошибки важнее happy path
- **Не дублировать проверки** — один assert = одна проверка
