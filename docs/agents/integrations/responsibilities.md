# Обязанности Integrations Agent

## Основные обязанности

1. Прочитать `API.md`, `swagger.json` из папки `docs/pm/features/{feature_task_id}/`; если в проекте есть `AGENTS.md` и/или папка `docs/features/` — прочитать их
2. Разработка Python/Node.js воркеров для фоновых задач
3. Интеграция с внешними API (Telegram, платёжные системы, SMS и т.д.)
4. Создание Dockerfile для каждого воркера
5. Документирование переменных окружения
6. Добавление новых env переменных в `.env.example`

## Definition of Done

- [ ] Прочитаны `API.md`, `swagger.json` из папки фичи (если есть)
- [ ] Воркер реализован и работает
- [ ] Dockerfile создан
- [ ] `workers/README.md` содержит описание, env переменные, команды запуска
- [ ] `.env.example` обновлён с новыми переменными
- [ ] Код закоммичен в репозиторий проекта
- [ ] Статус задачи обновлён на `completed`

## Выбор языка

| Сценарий | Язык |
|----------|------|
| ML, обработка данных, сложные алгоритмы | Python |
| Telegram боты, простые webhook обработчики | Python (aiogram) или Node.js |
| Высоконагруженные realtime обработчики | Node.js |
| Парсеры, scrapers | Python |

## Антипаттерны

- **Не хардкодить API ключи** — только env переменные
- **Не игнорировать ошибки** — всегда retry логика и логирование
- **Не создавать воркер без Dockerfile** — должен запускаться изолированно
- **Не забывать .env.example** — DevOps должен знать какие переменные нужны
