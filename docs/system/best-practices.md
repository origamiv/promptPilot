# Лучшие практики мультиагентной системы

## Выбор режима работы

### Когда использовать Auto-режим:

1. **Стандартные задачи**
   - Исправление багов с известным решением
   - Добавление новых эндпоинтов в существующую структуру
   - Создание простых CRUD операций

2. **Повторяющиеся операции**
   - Регулярные обновления зависимостей
   - Генерация документации
   - Запуск тестов

3. **Небольшие изменения**
   - Исправление опечаток
   - Добавление новых тестов
   - Незначительные правки интерфейса

### Когда использовать Approval-режим:

1. **Новые фичи**
   - Разработка новых модулей
   - Изменение архитектуры
   - Внедрение новых технологий

2. **Сложные задачи**
   - Многокомпонентные изменения
   - Интеграция с новыми сервисами
   - Глобальные рефакторинги

3. **Важные решения**
   - Изменение схемы БД
   - Новая архитектура API
   - Критические пользовательские сценарии

## Коммуникация между агентами

### Передача артефактов

```markdown
### Принцип передачи:
1. Parent task → Child task через prompt
2. Результаты дочерних задач доступны через parent_task_id
3. Все артефакты хранятся в репозитории
```

### Формат запросов агентов

```markdown
## Запрос к родительскому агенту

### Задача:
[Четкое описание задачи]

### Необходимые артефакты:
- [Список необходимых файлов/данных]
- [Контекст от других агентов]

### Ограничения:
- [Технические ограничения]
- [Временные рамки]
```

## Управление статусами

### Правила обновления статусов

```markdown
1. При старте задачи: pending → running
2. При завершении: running → completed
3. При ошибках: running → failed
4. При ожидании подтверждения: running → pending_approval
5. При замечаниях: pending_approval → in_progress
```

### Визуализация прогресса

```
┌─────────────────────────────────────┐
│ PM-задача [running]                 │
│   ├── Backend [completed] ✅         │
│   ├── Frontend [completed] ✅        │
│   ├── QA [running] 🔄              │
│   └── Reviewer [pending] ⏳         │
└─────────────────────────────────────┘
```

## Обработка ошибок

### Категории ошибок

1. **Временные ошибки** (Retry)
   - Network timeouts
   - Rate limits
   - Временные сбои API

2. **Логические ошибки** (Clarify)
   - Неясные требования
   - Конфликтующие задачи
   - Недостаточный контекст

3. **Архитектурные ошибки** (Escalate)
   - Невыполнимые требования
   - Конфликт с системой
   - Требуется решение человека

### Стратегии повторных попыток

```markdown
1. Автоматический retry (до 3 раз)
2. Увеличение интервала между попытками
3. Запрос уточнений при повторных ошибках
4. Эскалация к человеку при критических ошибках
```
