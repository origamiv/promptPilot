## Работа с Approval-режимом

### Цикл планирования и подтверждения

1. **Предварительное планирование**:
   - Агент анализирует задачу
   - Создает детальный план работы
   - Устанавливает статус задачи "Ожидает подтверждения"

2. **Подтверждение или замечания**:
   - Если пользователь подтверждает → агент начинает реализацию
   - Если пользователь предоставляет замечания:
     - Агент перемещает задачу в статус "В работе"
     - Создает новый план с учетом замечаний
     - Представляет исправленный план для повторного подтверждения

3. **Реализация плана**:
   - После получения подтверждения выполняет все шаги
   - Регулярно обновляет прогресс
   - При проблемах может запросить уточнения

### Обработка ошибок

### Если агент завершился с `failed`

1. PM-агент получает уведомление через опрос `GET /api/tasks/{id}`
2. PM анализирует ошибку в поле `error` задачи
3. Варианты действий:
   - **Повторный запуск** — если ошибка временная (rate limit, сеть)
   - **Создание уточняющей задачи** — агент получает дополнительный контекст
   - **Эскалация к человеку** — PM завершает свою задачу с `failed` и объясняет проблему

### Блокировки между агентами

| Агент | Ждёт завершения |
|-------|----------------|
| Database | Architect |
| Backend | Architect, Database |
| Frontend | Architect, UX |
| Mobile | Architect, UX |
| Integrations | Architect |
| QA | Backend, Frontend, Mobile, Integrations |
| Reviewer | Backend, Frontend, Mobile, Integrations |
| DevOps | QA, Reviewer |

## Статусы задач в pilot.our24.ru

| Статус | Значение |
|--------|----------|
| `pending` | Задача создана, ждёт исполнителя |
| `running` | Агент работает |
| `completed` | Агент завершил успешно |
| `failed` | Агент завершил с ошибкой |
| `rate_limited` | Превышен лимит API, ожидание ретрая |
| `cancelled` | Задача отменена (PM или человеком) |
