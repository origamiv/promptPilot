Справка: Канбан

Раздел Канбан показывает задачи в виде доски: каждая колонка соответствует одному из статусов справочника Статусы задач.

Устройство доски

  • Колонки формируются автоматически из активных записей справочника статусов.
  • Счётчик в заголовке колонки показывает количество задач в этом статусе.
  • Задача попадает в колонку по полю task_status_id. Если поле не заполнено, задача группируется по системному статусу через маппинг status_to.
  • Задачи без совпадения ни по одному критерию не отображаются на доске.

Карточки задач

  • Карточка содержит ID, заголовок (subject), аватар и имя исполнителя.
  • Нажмите на карточку, чтобы раскрыть полные детали: промпт, результат, метаданные.
  • Повторный клик сворачивает карточку.

Навигация по доске

  • Если колонок много, доска прокручивается горизонтально.
  • Кнопка Обновить в шапке перезагружает задачи с сервера без перехода в другой раздел.

Как назначить задачу в колонку

  • При создании или редактировании задачи выберите нужный статус из справочника.
  • Задача сразу появится в соответствующей колонке Канбана.
  • Для изменения статусов и цветов колонок перейдите в раздел Статусы задач.

Мультиагентная система в Канбане

Канбан показывает как обычные задачи, так и мультиагентные цепочки исполнения.

  • Если задача назначена на PM / Orchestrator, PM декомпозирует её на дочерние задачи для профильных ролей.
  • Если исполнитель не задан, задача идёт в базовый режим и выполняется одним агентом общей специализации.

Роли команды

  • PM / Orchestrator: распределяет работу и синхронизирует участников.
  • Architect, Backend, Frontend, Mobile, Database: реализуют профильные части решения.
  • UX Designer, QA, Reviewer: обеспечивают качество UX, тестов и итогового кода.
  • DevOps, Integrations: закрывают инфраструктуру, CI/CD и внешние интеграции.

Как читать прогресс мультиагентной задачи

  • Родительская задача описывает цель фичи и общий статус.
  • Дочерние задачи двигаются по колонкам независимо, по своим статусам.
  • Фича считается завершённой, когда закрыты все ключевые дочерние задачи и PM фиксирует итог.
