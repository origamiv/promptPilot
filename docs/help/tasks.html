Справка: Задачи

Раздел Задачи показывает очередь выполнения и историю запусков.

Что можно делать

  • Создавать задачу: выбрать провайдера, модель, приоритет, проект и текст промпта.
  • Фильтровать список по статусам: pending, running, completed, failed, rate_limited.
  • Открывать детали: результат, метаданные, стоимость, токены, время.
  • Управлять задачами: отмена, удаление, сброс зависшей задачи в очередь.

Как читать статусы

  • pending: задача ожидает запуска.
  • running: задача сейчас выполняется воркером.
  • completed: задача завершена успешно.
  • failed: выполнение завершилось ошибкой.
  • rate_limited: достигнут лимит API, будет повтор позже.

Мультиагентная постановка задач

Раздел Задачи поддерживает два сценария исполнения:

  • Если задача назначена на исполнителя с ролью PM / Orchestrator, PM получает верхнеуровневый запрос и создаёт дочерние задачи для профильных ролей команды.
  • Если задача не назначена на конкретного исполнителя, она уходит в обычный режим: выполняется одним агентом общей специализации без декомпозиции на подзадачи.

Роли команды

  • PM / Orchestrator: декомпозиция и координация.
  • Architect: системный дизайн и контракты API.
  • Backend: серверная бизнес-логика.
  • Frontend: Web UI и клиентские сценарии.
  • Mobile: мобильные приложения.
  • Database: схема БД, SQL и миграции.
  • UX Designer: UX-потоки и интерфейсные макеты.
  • QA: тест-планы и проверка качества.
  • Reviewer: code review и контроль регрессий.
  • DevOps: инфраструктура, CI/CD, деплой-контур.
  • Integrations: внешние интеграции и фоновые воркеры.

Как это работает на практике

  • Вы создаёте задачу и при необходимости указываете исполнителя.
  • PM-режим: появляется родительская задача и набор дочерних задач (parent_task_id) по ролям.
  • Single-agent режим: создаётся одна линейная задача без распределения по ролям.
  • Контроль прогресса ведётся через статусы задач и список дочерних задач в общей очереди.
